Action menus

Small menus for actions on a document or another application record. Keep a visible button, even when you offer a right-click shortcut.

Try two menus and a submenu · Run interaction and cleanup checks

Load only when needed

<link rel="stylesheet" href="/dist/action-menu.css">
import { createActionMenu } from '/dist/action-menu.js';
const menu = createActionMenu({ root: document.querySelector('[data-action-menu]') });
// When the owner unmounts:
menu.dispose();

Keep the regular Live Wires stylesheet. The optional entry does not change the default JavaScript bundle. Without enhancement, the scoped stylesheet leaves native actions visible as an inline list.

Server markup

<div class="dropdown" data-action-menu data-context-id="document-42">
  <button class="button trigger" data-menu-trigger type="button">Actions</button>
  <ul class="menu" id="document-menu" data-menu aria-label="Document actions">
    <li><button data-menu-action="duplicate" type="button">Duplicate</button></li>
  </ul>
</div>

Render only actions the current user may receive. A disabled or hidden item does not enforce permissions. The application must authorize every request.

Use unique menu IDs. A submenu opener is a button with data-menu-submenu and aria-controls pointing to its sibling ul.menu[data-menu]. Lists contain one native button or link per row; separators use a list item with an hr. Form inputs, navigation panels, details and dialogs keep their own native behavior.

Keys and focus

Enter, Space or a tap opens the menu. Up/Down opens at the last/first available item; arrows, Home/End and typing move focus. Forward arrow opens a submenu. Reverse arrow or Escape returns to its opener. Escape at the root returns to the visible button. Tab closes and lets the browser continue from that button. Clicking or focusing outside closes without taking focus back.

Intent belongs to the application

lw:menu-context fires before opening. Its detail contains the trigger, optional context target, context ID and activation source. A handler may replace authorized items synchronously. Cancel it to skip opening and preserve a native context menu.

lw:menu-action reports the action, context ID, trigger and chosen item, then dismisses. Cancel it when application code owns execution; cancellation also prevents a link or form button's native default. Neither event claims a save, deletion or successful response.

Updates and fallback

The application keeps the stable root and owns its server-rendered children. Replacing the menu closes the old levels. Removing the trigger or root disposes the adapter. Added, disabled and hidden items refresh while open. Call dispose() before unmount when possible; repeated cleanup is safe. A detached menu never remains as an overlay.

These are live lists, not cloned HTML templates. Replace the list with newly rendered template output. No Rocket, Datastar adapter, endpoint binding or global command framework is installed. Without the optional module or Popover API, native forms and links can still execute application-supplied fallback actions; a data-action button alone needs an application handler.
