Edit a value in place, preserve the draft, and wait for application confirmation.

Compact editing

The value and small accent ghost Edit control share a row. Edit replaces them with a small field, Save and ghost Cancel. The field stays in place while you type or wait for a response.

Keyboard, drafts and application results

Use Edit, Enter, Space or F2 to begin. Save or Enter submits the draft. Escape or Cancel ends editing. Leaving the field keeps your draft and never saves.

This page simulates application results. Without JavaScript, compact editing shows a native form; the disclosure opens one. Submitting reloads this example and saves nothing.

Rejection keeps the entered value and associates the error with the field. Pending and uncertain values remain visible and read-only. Cancel is always a ghost action and does not promise to undo a pending save.

Optional setup

Link /dist/inline-edit.css after /dist/main.css, import createInlineEditor from /dist/inline-edit.js, and attach it to each stable editor root.

import { createInlineEditor } from '/dist/inline-edit.js';
const editor = createInlineEditor({ root });
root.addEventListener('lw-inline-edit-commit', async ({ detail }) => {
  const { contextId, editId, requestId, value, original } = detail;
  // The application returns an authoritative value only after confirmed saving.
  try {
    const result = await applicationSave({ contextId, value, original });
    editor.applyResult({ contextId, editId, requestId, ...result });
  } catch {
    editor.applyResult({ contextId, editId, requestId, outcome: 'unknown' });
  }
});

applicationSave is your application code. Map transport uncertainty to unknown; request completion alone never means saved. Results must match the context, edit and request IDs.

Preserve the root, field and other required nodes during unrelated updates. The controller preserves draft and selection; your application must preserve the focused input during its own DOM updates.
