People picker

Choose who belongs to a space, a circle or a draft, by circle and by person.

When to use it

Use a people picker when someone chooses a set of members from a known list: the members of a space, the people in a circle, a draft's collaborators. It shows everyone who could be chosen, whether each person is in, and why.

For finding one person in a large directory, use a search field instead. A picker lists people; it does not page through thousands.

The HTML contract

A fieldset.people-picker holds the whole control. Inside it, in reading order: the legend, an optional description, optional group toggles, the table of people, a status line and optional actions. Each row has a selection cell and a member cell, plus an optional trailing control cell.

<fieldset class="people-picker" id="members-picker">
  <legend>Members</legend>
  <div class="people-picker-groups" role="group" aria-label="Circles">
    <button type="submit" class="button button--small" name="picker_action"
            value="circle:board" aria-pressed="true" formnovalidate>Board</button>
  </div>
  <table class="people-picker-table table--lined">
    <thead><tr>
      <th scope="col"><span class="visually-hidden">Select</span></th>
      <th scope="col">Member</th>
      <th scope="col">Organizer</th>
    </tr></thead>
    <tbody>
      <tr>
        <td class="people-picker-select">
          <label class="checkbox checkbox--icon">
            <input type="checkbox" id="pick-ada" name="member_ids" value="ada"
                   aria-describedby="pick-ada-detail" checked aria-labelledby="pick-ada-label">
            <span class="visually-hidden" id="pick-ada-label">Select Ada Okafor</span>
          </label>
        </td>
        <td>
          <label class="people-picker-person" for="pick-ada">
            <span class="avatar avatar--sm"><span class="initials" aria-hidden="true">A</span></span>
            <span class="people-picker-name">Ada Okafor
              <span class="people-picker-detail" id="pick-ada-detail">Organizer, Board</span>
            </span>
          </label>
        </td>
        <td class="people-picker-trailing" data-th="Organizer">
          <label class="switch switch--small">
            <input type="checkbox" role="switch" name="organizer_ids" value="ada"
                   aria-label="Make Ada Okafor an organizer" checked>
            <span></span>
          </label>
        </td>
      </tr>
    </tbody>
  </table>
  <p class="people-picker-status visually-hidden" role="status" aria-atomic="true"></p>
  <div class="people-picker-actions">
    <button type="submit" class="button button--small"
            name="picker_action" value="clear" formnovalidate>Clear selection</button>
  </div>
</fieldset>

Hook reference

.people-picker
The fieldset. It removes the default fieldset border and padding and spaces its parts. Put it inside your own box or panel.
.people-picker-description
Optional short text under the legend, such as who can see the result. Also used for an empty state.
.people-picker-groups
A role="group" row of button button--small toggles. aria-pressed="true" marks a selected group and styles it as an accent button, so there is no second class to keep in sync. A disabled toggle stays visible.
.people-picker-table
Use with table--lined. The selection and trailing columns shrink to their controls; the member column takes the rest.
.people-picker-select
The cell holding the row's checkbox checkbox--icon.
.people-picker-person
A label for the row's checkbox containing an optional avatar and the name. Clicking the avatar or name toggles the checkbox. It uses the regular weight that labels otherwise lose.
.avatar
Optional. Use the avatar component as documented, usually avatar--sm with one initial. The visible name already identifies the person, so the avatar is decorative: give an image alt="", and leave out the role="img" and aria-label an initials avatar uses elsewhere.
.people-picker-name
The person's name. Long names wrap instead of widening the table.
.people-picker-detail
Optional muted line under the name: why the person is included, such as "Organizer, Board", or "Removed". Point the checkbox's aria-describedby at it.
.people-picker-trailing
Optional end cell for one control per person, such as a small switch or a role field. Its column header names the control. Repeat that text in the cell’s data-th attribute so the label stays visible when narrow tables hide their headers.
.people-picker-status
A role="status" line for changes that affect many rows, such as "Selection cleared". Keep it in the page from the start and change its text; usually also visually-hidden.
.people-picker-actions
Optional row for buttons such as Clear selection or More people.

States

  • Selected. A checked row checkbox. Show the reason in the detail line.
  • Selected group. A toggle with aria-pressed="true". Selecting a group should check its members; whatever applies that rule also updates the rows.
  • Removed. A person a group would include but who was taken out. Leave the checkbox unchecked and say "Removed" in the detail line.
  • Locked. Someone who cannot be changed here, such as the creator or a super admin. Disable the controls that cannot change and say why in the detail line. A disabled control is not submitted, so whatever processes the form must keep that person's state.
  • Unavailable group. A disabled toggle, with a sentence after the group row explaining why.
  • Empty. No table. Use a .people-picker-description that says no people are available.

Accessibility

  • The legend names the whole control. Give the group row an aria-label, such as "Circles".
  • Give the hidden “Select Ada Okafor” span a unique id and point the checkbox’s aria-labelledby at it. The member cell’s label for keeps the name and avatar clickable without repeating them in the accessible name. Use aria-describedby for the separate detail line.
  • The select column header is visually hidden text, not empty, so the column still has a name.
  • A switch or field in the trailing column needs its own name, for example aria-label="Make Ada Okafor an organizer" or a visually hidden label for.
  • Announce changes to many rows through the status line, not by moving focus.
  • Keep the native checkbox and switch inputs. They work with the keyboard and without JavaScript.

Keeping the rules on the server

The picker carries state only. Which people a group adds, who is locked and what each detail line says are rules for the page that owns the data. A reliable way to apply them is to let the server re-render the picker after every change.

  • Make group toggles and Clear selection named submit buttons, such as name="picker_action" value="circle:board", with formnovalidate. Without JavaScript they submit the form and the server returns the page with the change applied.
  • With Datastar, post the form from each toggle's click and each checkbox or switch's change, and have the server patch the whole fieldset back by its id. The browser then holds no access rules.
  • Check the final submit again on the server. A checkbox can change after the last preview returned.
