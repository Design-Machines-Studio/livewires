Sortable list

This optional enhancement keeps the list in its authored order until your application confirms a move. It sends a request; your application decides whether and how to apply it.

This static reference includes a small local responder so the interaction can be tried. It updates the list as the application would, then confirms the matching request. It is not persistence or a server integration; use the manual fixture for delayed, rejected and stale response cases.

Use the handle and arrow keys to stage a position, Space to request it, and Escape to cancel. Pointer and touch dragging announce the staged destination and cancel when released outside the list. The move buttons request the previous or next position directly. In an application, point each form to its own reorder endpoint for a no-JavaScript fallback.

Contract

The component emits a bubbling sortable-move-request event with { itemId, before, requestId }. An empty before means append at the end. Apply authorized, authoritative markup first, then call list.resolveMove({ requestId, status, message? }) with accepted or rejected. Only a matching result clears the pending request. The opaque request ID correlates this UI response; it is not an authorization or idempotency token. The component does not persist, authorize, retry, or reorder the list.

list.addEventListener('sortable-move-request', async (event) => {
  const { itemId, before, requestId } = event.detail;
  const result = await saveAuthorizedMove({ itemId, before });
  renderAuthoritativeList(result.items);
  list.resolveMove({ requestId, status: result.accepted ? 'accepted' : 'rejected' });
});

Use data-sortable-list, data-sortable-item, a unique data-item-id, data-sortable-handle, optional data-sortable-move="up|down", and data-sortable-status. Component styles use those hooks for the staged source, target, end cue, pending state and status. The handle and move forms are authored controls. Change each example form’s action and before value to match an application endpoint and current order for a server fallback if the optional module fails.

Load /dist/sortable-list.js and /dist/sortable-list.css only on pages that use the element. It is outside main.js. Removing an instance cancels staging and invalidates its outstanding request; reinsertion attaches one listener set and ignores old results. A consumer must render its accepted order before calling resolveMove. The component never observes DOM changes as confirmation.
